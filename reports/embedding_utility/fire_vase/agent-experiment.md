# Next milestone: controlled agent selection

Status: the controlled harness is **WORKING** and the complete **MOCKED** matrix is
executed. Real-model smoke remains **PLANNED**. See [milestone 2 report](milestone-2-report.md)
and the [frozen protocol](agent-protocol-v2.md). This original next-step outline is
retained as history; no real-model calls or runtime scientific code generation occurred.

1. Wrap existing benchmark registry IDs in a typed decision envelope: select one
   offered operation with caller-supplied task/fire IDs and schema-permitted date or
   candidate parameters, or abstain with evidence references. Do not expose worker
   interpreters, PCA fitting, arbitrary functions, SQL or source paths as model tools.
   Runtime requests cannot change units, tolerance, permissions or answer keys.
2. Give the same model/system instruction and resource budget each prebuilt
   M0/M1/M2 evidence view. Keep graders, reference answers and answerability maps
   private. Supply only R0, R1 or R2 allowed data/consumers for that arm; no silent
   raw fallback. The full canonical validator always retains scientific preconditions.
3. Add a finite, versioned operation/step and token/time budget. Keep separate
   experiments for strict interfaces versus an explicit source-fallback policy.
   Cache state/prefill and cold/warm ordering must match across metadata conditions.
4. Verify the actual installed runtime contract (including OpenClaw version if used),
   exact returned provider/model, prompt/schema identities and stochastic settings.
   Store exact prompts, normalized response scope, outputs, timestamps and actual
   usage. Missing usage is unknown, not an invented token count. No repairs or mocks
   on invalid/truncated output or unavailable services; retain failures and vetoes.
5. Reuse independent evaluator answers for exact/geometry tasks. Validate final
   answer types, units, source citations and numerical tolerances. Penalize invented
   values from insufficient views even when accidentally numerically correct.
   Distinguish justified abstention, tool rejection, invalid decision and execution
   failure. Deterministic non-execution is not demonstrated model competence.
6. Separate development tasks/fires from hidden evaluation templates and events;
   the checked-in synthetic answer suite is a development diagnostic, not a secret
   generalization test. Pair tasks across arms, randomize order and repeat model
   samples; repeated calls do not create independent scientific cases.
7. Begin with one fixed model and exact/profile/geometry families. Size the initial
   dry run from instrumentation needs, then choose confirmatory group counts from
   practical effect/precision targets. The old 288-call agent pilot remains an
   unapproved budget proposal, not a run performed by this milestone.
8. For real data, review a bounded input manifest, cumulative-versus-ring semantics,
   source rights/support, observation uncertainty and availability before access.
   Independent similarity requires expert relevance. Forecasting needs a reviewed
   prefix-only recipe. Full-history normalization is prohibited in prefix inputs.

Minimum additional implementation: validated agent decision contract; provider
adapter with exact identity/trace preservation; budgeted dispatcher over the existing
registry; final-answer validator; frozen prompt/evidence renderer and paired-run
scheduler. No neural encoder or unrestricted programming is needed for this first
agent experiment. Production review gates and historical vetoes remain unchanged.

Before confirmatory cost claims, add and independently validate targeted direct
statistics where the current R0 interface reuses a whole upstream feature bundle.
Do not mistake worker IPC or tool-granularity differences for irreducible value of
embedding. Retained source-ID counts must remain available to all permitted views;
metadata/provenance can answer some questions without numerical inversion.
