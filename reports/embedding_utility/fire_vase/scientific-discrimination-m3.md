# Scientific discrimination audit

Read together: M1 implementation/report, M2 protocol/report, development ledger,
original 29 questions, Fraction/SVD references, operation registry, implementation
plan, saved access check and inert held-out-pending config. This audit preserves
those artifacts and their actual limitations.

| Contrast | Original evidence | Limitation | Expanded test |
| --- | --- | --- | --- |
| Native vs compressed | Area/dates/gap increments unavailable from R1/R2 | Mostly obvious operation/access separation | New dated endpoint contrasts, missing/omitted/unknown-baseline cases; independently differenced keys |
| R1 vs PCA | Full profile exact; R2 neighbor fidelity miss | One neighbor case, no discarded-error audit | Residual norm, rank stability, full vs declared projected distance, pulse count vs dates |

| Metadata vs access | M0/M1/M2 invariant capabilities | Mock ignores metadata | Frozen evidence-only treatments and negative controls; real metadata effects remain unmeasured |
| Efficiency vs sufficiency | Cold/warm query timings | R0 front statistic computed all traits | Indexed lookup, targeted linear CDF integrals, cached direct computation, preparation/amortization/routing charged |

R0-first equals fixed R0 partly because of mock policy and partly because R0
informationally dominates deterministic functions R1/R2. The original task design
had little cost-sensitive selection pressure and an unoptimized scalar path. None
of these facts establishes that adaptive routing should improve accuracy. A better
representation can reduce work without increasing available information, or lose
useful information despite fast lookup. The expanded benchmark can show either.

Scientific question types are distinct from independently adjudicated science.
Arithmetic/geometry keys are separately implemented mathematical checks. Draft
source-evidence claim rubrics are assistant-authored and require expert review.
Mathematical neighbor identities never become ecological relevance labels.
